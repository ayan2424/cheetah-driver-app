Product Overview

The Cheetah Driver & Warehouse Picker Mobile App is an enterprise-grade cross-platform solution developed with Flutter 3.x and Dart 3.x. It connects natively with the Cheetah Courier Management System or any modern logistics REST API backend to provide real-time fulfillment, live driver tracking, barcode item verification, and contactless proof-of-delivery (POD).

Driver Delivery Engine
Smart parcel routing, live navigation, one-tap phone calls, OTP delivery verification, and digital signature capture.
WMS Warehouse Picker
Real-time pick task queue, zone/aisle/shelf routing, and instant camera barcode scanning.
Real-Time Telemetry
Continuous background GPS broadcasting with anti-tampering hardware enforcement and battery optimization.
COD Ledger & Wallet
Live calculation of collected cash, pending branch vault deposits, and driver financial transaction records.
AES Encrypted Offline Queue
Delivers zero-data-loss in basements or remote areas. Syncs queued PODs automatically upon network recovery.
Multi-Language Ready
10+ pre-translated languages including English, Spanish, Arabic (RTL support), French, German, and Urdu.

Configuring API Endpoints

Connecting the mobile app to your live Cheetah Courier Management System backend takes less than 30 seconds.

Single File Config: All network endpoints are centralized inside lib/utils/constants.dart.
lib/utils/constants.dart
class AppConstants {
  // 1. Replace with your live backend domain (Must include trailing slash and HTTPS)
  static const String baseUrl = 'https://your-domain.com/';
  
  // 2. Standard REST API endpoints for Driver and Picker
  static const String apiUrl = '${baseUrl}api/v1/driver/';
  static const String pickerApiUrl = '${baseUrl}api/v1/picker/';
}
SSL Requirement: Modern Android and iOS systems reject cleartext (http://) requests. Ensure your backend has an active SSL certificate (https://).

Offline-First Architecture & AES Hive Queue

Drivers frequently operate in basements, high-rise elevators, and remote areas with zero cell signal. The app features a resilient offline queue system:

1. AES-256 Encryption
When offline, complete POD records (photos, signatures, customer info) are encrypted with AES-256 before being written to disk via Hive.
2. Auto Connectivity Listener
The app monitors real-time network states using connectivity_plus.
3. Background Sync & Flush
Upon internet reconnection, queued tasks are flushed sequentially with automatic retries and deleted only after server 200 OK response.

Live GPS Telemetry & Hardware Guard

To prevent drivers from faking location or turning off GPS during shifts, the app implements hardware-level event listeners:

Anti-Tampering Guard: If a rider disables GPS in OS quick settings, the app instantly catches the hardware event, transmits a gps_enabled: 0 alert to the admin dispatch map, and locks the screen with a mandatory prompt to re-enable location.

Troubleshooting & FAQ

How do I test the app on a local computer without a domain?
Use your computer's local Wi-Fi IP address (e.g. https://192.168.1.50/) in lib/utils/constants.dart. Ensure your phone and computer are on the same Wi-Fi network. Do not use localhost or 127.0.0.1 as physical mobile devices refer to themselves with localhost.
Why does the camera barcode scanner show a black screen in the simulator?
Emulators and simulators do not have physical camera sensors. Barcode scanning and photo capturing must always be tested on a physical Android or iOS device.
How do I fix CocoaPods version errors on macOS?
Open terminal in project root, run cd ios && rm -rf Pods Podfile.lock && pod cache clean --all && pod install --repo-update && cd .. and restart Xcode.
